# Architect — NBT Parsing Interface (M1)

Source of truth: `src/architect/nbt/Nbt.h`.

## What exists in M2 (updated 2026-10-13)

- **Tag parser: IMPLEMENTED + EXECUTED** (`Nbt.cpp`,
  `readRootCompoundFromMemory`): big- and little-endian, all 12 payload
  types, bounded cursor (truncation → `ParseError`, never over-read),
  nesting cap (64), array sanity caps, trailing-bytes rejection. Throws
  nothing. Verified by `tests/cpp/TestNbt.cpp` — **executed locally
  with MSVC 14.51 (`cl /std:c++20 /W4`), all green** (see
  `docs/ENGINEERING_REPORT_M2.md`).
- **gzip inflate: IMPLEMENTED + EXECUTED** (`Gzip.cpp`,
  `decompressGzip`): container + stored/fixed-d Huffman blocks, CRC32
  and ISIZE verification, output cap, trailing-member rejection.
  `.litematic` file bytes now decode end-to-end through
  `readLitematic(bytes)` (see `ENGINEERING_REPORT_M2_FOLLOWUP.md`).

## Backend decision (M2-follow-up outcome: zero dependencies, FINAL)

The M1 plan named `mcnbt`/`nbt-cpp` + zlib; M2 hand-rolled the parser;
the follow-up hand-rolled gzip too (`src/architect/nbt/Gzip.{h,cpp}`:
RFC 1952 + 1951, stored/fixed/dynamic blocks, CRC32 + ISIZE verification,
256 MB bomb cap, single-member strictness). **No NBT library and no
zlib will ever be needed.** Rationale: the full input surface (gzip +
12 tag types, both endians) is now implemented in ~700 lines of
dependency-free code with 40+ executed checks; a third-party dependency
would add review surface for zero capability gain.

## Conformance target (what "done" means) — MET

`tests/cpp/TestGzip.cpp` starts from a real gzip-compressed
`.litematic` file and verifies compressed file → inflate → NBT parse →
decode → model (2 regions, 28 cells, palettes, tile entities), plus
corrupt gzip headers, truncation, CRC/ISIZE mismatch, cap overflow,
trailing members, and invalid NBT. Vectors in
`tests/cpp/GzipVectors.h` (generated by `tools/gen_gzip_vectors.py`
from CPython's zlib) pin empty/stored/fixed/dynamic/named members.

## Conformance target (what "done" means)

The C++ backend must decode the checked-in fixture byte-for-byte
identically to the pure-Python reference parser: same root tags, same
palette entries, same per-cell ids, same rejections (bad `Version`,
short `BlockStates`, out-of-range id). The Python tests are the
specification until the C++ tests (`tests/cpp/`) can run under xmake.
